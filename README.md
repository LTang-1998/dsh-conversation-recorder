# dsh-conversation-recorder

把 DSH 会话实时记录成**可读的 Markdown 链**，供人翻阅、也供其他 agent 当记忆读取。

每个会话落成 `<记录根>/<工作区文件夹>/<sessionId>/` 下的一对东西：

```
index.md            # 会话索引：frontmatter 元数据 + 轮次表
turns/0001.md       # 逐轮正文（4 位零填充序号）
turns/0002.md
```

默认记录根是 `<$DSH_HOME>/_conversations`（`$DSH_HOME` 语义同 DSH 自带 `resolveDshHome()`：
显式值 → `$DSH_HOME` → `~/.dsh`）。**不配也不再跟着每个会话自己的 cwd 跑**，所有记录集中在一处，
方便别的 agent 按工作区分区去读。

- 契约（唯一契约来源）：[SPEC.md](SPEC.md)

## 安装

```
dsh plugin --profile <你的 profile> add github:LTang-1998/dsh-conversation-recorder#v1.0.0
```

**装完即可用，不需要构建授权**：`lib/`（预构建产物 + 类型声明）已随仓库提交，`cordis.patch.yml`
按**包名**引用本包，入口是 `package.json` 的 `main`/`exports` → `lib/index.js`。

> 为什么以前装不上：早期形态把插件行写成相对源码路径 `./src/index.ts`，别人正常安装后 Node 在
> `node_modules` 下遇到 `.ts` 会直接报 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`。
> 现在入口是预构建的 `lib/index.js`，没有这个问题。

重启 DSH 才生效：插件由会话生命周期事件驱动，**安装/更新后需重启该 profile 的 DSH**。

## 兼容性

- **DSH**：针对 **0.2.1-rc.2** 开发与验证（`engines.dsh: ^0.2.1-rc.2`），**未在其他版本上验证过**。它绑定这些宿主内部契约，升级 DSH 时请留意：会话事件 `session/created`/`session/event`/`session/disposed` 及载荷形状；`tool/result` 的 `message.toolCallId ?? message.source.callId` 与消息 content 里的 text 块（v4 无 `tool-result` 包壳）；插件 `Config` + `.volatile()` 的 `config.<field>.get()` 读取模型与 `settings.configure({auto:false})` 接线；客户端 `settings.section` 槽与 `configForms` 的 `getSnapshot`/`subscribe`/`set`。

## 它记什么

| 你会看到 | 内容 |
| ---- | ---- |
| `index.md` 的 frontmatter | `title` / `session` / `started`（UTC）/ `model` / `turns` / `fork_from` |
| `index.md` 正文 | 三列轮次表 `\| seq \| time \| kind \|`（由磁盘现状重建，不另存内存表） |
| `turns/NNNN.md` 的 frontmatter | `session` / `seq` / `time`（UTC）/ `kind` / `prev` |
| `turns/NNNN.md` 的 `## user` | 人直接输入的提问 + 另一个 agent 发来的消息（插件注入的上下文**不入正文**） |
| `turns/NNNN.md` 的 `## assistant` | agent 回答正文 |
| 工具清单行 | `- [callId前12] 工具名 参数预览 → 结果X行 [error:code]` |

- **叙事链**：`prev` 指向上一条记录，顺着读就是完整对话；fork 出来的会话首轮 `prev` 跨目录指向
  父会话的 fork 点（`../<父会话id>/turns/NNNN.md`）。
- **序号只增不减**：`seq` 取「该会话磁盘上已存在的最大序号 + 1」。如果某轮当年没落盘（写盘失败、
  或文件后来被删），那个号会被**跳过**而不是回填——所以 `turns/` 里可能缺号，`index.md` 的
  `turns`（文件个数）也可能小于最大序号。这是有意的：洞若被回填，链上的轮次身份会漂移；而当
  最大序号远大于个数时，回填口径会跟「已有文件不覆写」互锁，把后续记录**永久卡死**。
- **重启/重开不丢**：登记时机是「首次见到该会话的事件」，插件停用重开或进程重启后，正在跑的会话
  只要再更新一次轮次就自动接上并续号。
- **不回溯**：插件启用前就结束的老会话不会补记（要补得解析 `sessions/` 原始日志，不在本插件范围）。

## 设置

命名空间 `dsh-conversation-recorder`（= profile 里的插件条目 id）。插件 `export const Config`，五个字段
全部 `.volatile()`——宿主每次读取都是当前值，所以**改完即时生效，不用重启**。
两种改法：DSH 设置页的「会话记录」分区，或写 profile 的 `cordis.patch.yml` 里本插件条目的 `config`：

```yaml
- id: dsh-conversation-recorder
  config:
    root: D:\知识库\_conversations
```

| 字段 | 类型 | 默认值 | 说明 |
| ---- | ---- | ------ | ---- |
| `enabled` | boolean | `true` | **总开关**。关掉后立即停止产出新文件：不落盘、不补写 index、连目录都不建；进行中的那一轮整轮丢弃（不留半份、不占序号）；**不删任何已有内容**。改回 `true` 后下一次轮次事件立即恢复 |
| `root` | string | `<$DSH_HOME>/_conversations` | 记录根；**唯一来源就是 `Config.root`**（空串回退内置默认）。支持开头 `~` 展开 |
| `recordSubagents` | boolean | `false` | 打开后子代理会话（`header.origin === 'subagent'`）也记录 |
| `toolArgsPreview` | number | `40` | 工具清单行参数预览字数（0–200，越界由 schema 拒绝） |
| `emptyIndex` | boolean | `false` | 打开后元数据事件（`session/title` / `request/context`）也建目录并写 index；默认只有首个内容轮次落盘才建目录（不产生空壳） |

**换 `root` 的已知行为**：认已有记录靠磁盘（`<root>/<工作区>/<会话id>/` + `index.md` + `turns/`），
所以某个会话当初记在别的 root 下、你改了 root 之后，它在**新根下认不出来**，会从 `0001` 重开；
旧根下的记录不迁不删。

### 记录根下自动生成的两份说明

首个内容轮次落盘后，插件确保记录根下存在 `README.md`（给人看）与 `AGENTS.md`（给读这份记录的
agent 看），首行都带生成标记 `<!-- generated by dsh-conversation-recorder -->`。

**只缺则写**：文件已存在就一个字节都不动——包括没有生成标记的**手写文件**（那种情况只在 stderr
提示一行）。`AGENTS.md` 上限 2KB。想自己写说明，直接把文件放进去即可，插件不会覆盖。

## 依赖边界

- **运行时依赖白名单恰好两项**：node 内置之外，`src/**` 只允许运行时 `import` DSH 随装提供的
  `@deepseek-ai/schemastery`（设置 schema 的真构造器）与 `@deepseek-ai/dsh-home-paths`（内置默认根
  真调 `resolveDshHome()`）；其它任何裸包名（含其它 `@deepseek-ai/*`）都被 `tests/run.ts` 的 R9 红线挡住。
  二者按 `peerDependencies`（optional）声明，同时**钉版本**列在 `devDependencies` 供开发与 CI 解析
  ——`dependencies` 为空，插件运行时解析的是**宿主**那一份。
- 类型只 `import type` 自 `@deepseek-ai/*`（编译期擦除），所以运行时不会真的加载它们。

## 开发

改 `src/**` 之后**必须重跑构建并把 `lib/` 一起提交**——`lib/` 是安装时真正加载的产物，
源码与产物不一致会让「装得上」直接失效。`pnpm verify` 就是这条的机器判据。

```
pnpm install           # devDependencies（类型门禁用；运行时只依赖宿主自带的两个 peer）
pnpm build             # 构建 lib/（宿主半边 + 客户端半边）
pnpm typecheck         # 宿主侧类型门禁
pnpm typecheck:client  # 客户端半边类型门禁
pnpm test              # node tests/run.ts
pnpm verify            # pnpm build && git diff --exit-code -- lib（产物与源码一致性）
pnpm verify:privacy    # 全仓扫机器特定路径（盘符用户目录 / POSIX 用户家目录）与真实会话 id
```

### 测试与验收命令

```
node tests/run.ts                       # 验收测试：通过 64 / 失败 0 / 跳过 0
node tests/spec-selfcheck.ts            # SPEC 结构自检（绿）
node tests/probe-real-settings.ts       # 只读探针：本机声明的 root → Config → 落点
node tests/probe-client-bundle.ts       # 只读探针：lib/client.js 自注册/物化/槽注册链
```

CI 按 **node 22 与 node 24** 各跑一遍上面的门禁（`.github/workflows/ci.yml`）。

### 源码约束（类型擦除红线）

`tests/run.ts` 用 **node 直接执行 `.ts`**（Node ≥ 22 的类型擦除，无构建步骤）驱动 `src/`，
因此源码只能用**可擦除语法**：

- **禁** `enum`、**禁** `namespace`、**禁**构造函数参数属性（`constructor(private x: T)`）、
  **禁** `import x = require()` / `export =`；
- 类型引用一律 `import type …`；唯一的运行时例外是 §9 白名单里的两个宿主 peer
  （`@deepseek-ai/schemastery`、`@deepseek-ai/dsh-home-paths`）；
- 相对导入必须带 `.ts` 扩展名（`./engine.ts`），因为运行时不做扩展名补全；`build.mjs` 会把
  产物 `d.ts` 里的这些说明符改写成 `.js`。
- **客户端半边例外**：`src/client/**` 的相对 import **不带**扩展名（`build-client.mjs` 用
  `tsc --noResolve` 直出 CJS 装进 bundle 的本地模块表，带 `.ts` 会触发 TS5097）；因此客户端
  新增流程不能另开相对模块给 node 侧测试 import，只能挂在已有 import 链的模块上。

### 构建产物说明

`pnpm build` 做三件事：`tsc -p tsconfig.build.json` 产出 `lib/` 宿主半边；把 `lib/*.d.ts` 里相对
导入的 `.ts` 扩展名改写成 `.js`；`build-client.mjs` 把 `src/client/*.ts` 用 `tsc`
（`--module commonjs --noResolve`）编成 CJS，装进 bundle 内部的本地模块表，再套
`window.__ModuleLoader__.load({ id, factory })` 脚手写成 `lib/client.js` + `lib/client.d.ts`。

客户端半边**不引入任何打包器依赖**：`react` 与 `@deepseek-ai/*` 保持外部（由 shell 基线模块表回答），
产物里不内联宿主库。类型环境是入库的 `src/client/env.d.ts`，构建与 `tsconfig.client.json` 门禁共用。

### 设置页分区

`src/client/index.ts` 注册 `settings.section` 槽（`id: conversationRecorder`，标签「会话记录」），
控件全部来自宿主自带的 `@deepseek-ai/dsh-client-ui-primitives`（`Input` / `Button`）+ DSH 设计变量
（`--dsw-alias-*`），**没有裸 `<input>`/`<button>`/`<label>`**；**不给 `Input` 传 `style`**（官方
`Input` 的 `style` 会打进内层内容层，外框里套小框、两个框大小不一致）。

读写走宿主 `configForms` 服务：`ctx.configForms.get('dsh-conversation-recorder')` 取 `ConfigForm`，
读用 `getSnapshot()`/`subscribe()`，写逐字段 `await form.set(field, value)`——revision 校验、失败回读、
写入排队都由宿主负责，客户端不再自己解信封、也不自增版本号。读/写失败显示在分区状态行；
客户端半边挂载失败不影响宿主记录（`apply()` 包 try/catch）。

## 契约摘要

| 文件 | 内容 |
| ---- | ---- |
| `<工作区文件夹>/` | 记录根下的分区第一级，名字由会话 cwd 按 SPEC §2 规则转义（cwd 缺失 → `未分组`） |
| `index.md` | frontmatter `title/session/started/model/turns/fork_from` + 正文轮次表 `seq\|time\|kind` |
| `turns/NNNN.md` | frontmatter `session/seq/time/kind/prev` + 正文 `## user` / `## assistant` 小节、引用行、工具清单行 |

工作区文件夹名规则：去 `:`，`\` 与 `/` 都换成 `-`；连续非 ASCII 段保留可读形式并紧跟每个 UTF-16
码元的 `~XXXX`；`* ? " < > \|`、`# ^ [ ]`、`~` 各转义成 `~XXXX`；cwd 缺失或为空 → `未分组`。
例：`D:\我的笔记` → `D-我的笔记~6211~7684~7B14~8BB0`，`D:\示例` → `D-示例~793A~4F8B`。

完整契约（含字段表区块）见 [SPEC.md](SPEC.md)。
